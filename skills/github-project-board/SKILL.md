# GitHub Project Board

Read selected modern Project items or apply exact approved **Status** values. A board column is a presentation of a Project field, not an ADO state mapping or GitHub Issue state. No inferred readiness/blocker policy, general field editor, or Issue close/reopen automation.

## Inputs and contracts

Read [COMMON](../../references/COMMON.md), relevant adopted [PROJECT_CONTEXT](../../references/PROJECT_CONTEXT.md), [GITHUB_MUTATIONS](../../references/GITHUB_MUTATIONS.md), and [github-operations](../github-operations/SKILL.md). Require exact host/connection, owner kind/login + Project URL/number/verified node ID, selected item/Issue identities or bounded read query, and read purpose. Writes additionally require selected item IDs, discovered single-select Status field/option IDs, exact before -> intended values, unchanged-batch approval, explicit residual-race acceptance and approved durable manifest/checkpoint paths. A publishing handoff may supply approved typed item-ID bindings; verify them, not a title match.

Unknown field/type/option, ambiguous owner/Project/item identity, redacted content needed for verification, required CAS, or missing authority blocks mutation. Offer a partial snapshot/proposal and targeted questions rather than inventing columns or business rules. Read-only requests never authorize updates.

## Workflow

1. **Resolve and discover.** Verify exact Project owner kind/host/ID and current visibility/access. Discover Project fields with types and single-select option IDs/names; identify the intended `Status` field explicitly. Missing/renamed/ambiguous/non-single-select fields require user mapping or a blocked result; never create a field/option or choose a similar label. Read-only work can report absent Status without repair.
2. **Collect bounded snapshot.** Enumerate selected items or paginate declared scope, including nested field values. Record item node ID separately from content Issue/PR/draft identity, repository, Issue state and selected Status (including unset). Track redacted, inaccessible, archived, duplicate and missing items and truncated collections. Do not misclassify an Issue as absent/deleted based on a filtered view or unreadable content. Default mutation scope is verified repository-Issue-backed items; PR/draft/redacted/archived targets are read-only in this MVP. Show complete-within-scope versus partial coverage and timestamps.
3. **Propose exact deltas.** For each selected verified Issue-backed item, show Project/item/Issue tuple, Status field ID/type, current option ID/name or unset, and intended **existing** option ID/name. No bulk “move everything in column” inferred from an analysis. Already at target is a no-op with verification, not a write. Do not set Issue state, labels, other fields, or a field clear operation. Exact option selection is a user/workflow decision, not derivable from names like Done.
4. **Approve durable boundary.** Use [run records](../github-operations/run-records.md): immutable exact payloads or fully approved placeholders, baseline and source/hash where relevant, narrow preflight/read-back expectations, no-actions, durable paths, retry/continuation bounds. Disclose that immediate re-read is optimistic and cannot prevent a concurrent edit after it. Proceed only with explicit acceptance of that risk; block if atomic conflict prevention is required. An unchanged publishing manifest may carry this approval; do not require duplicate approval. Recheck public Project/repository visibility and approve any public-facing Status/metadata change.
5. **Re-read immediately, then update once.** Confirm authentication/visibility, exact Project membership/Issue identity, non-archived item, Status field/type/options and current Status against approved baseline. Missing option, automation/user change, different baseline or changed scope stops for rebase/new approval; do not overwrite. If unchanged, record attempt and send only the approved selected-field assignment using verified current transport schema. The documented GraphQL operation is `updateProjectV2ItemFieldValue` with `value.singleSelectOptionId`; do not treat that as a tool name. Add-to-Project is a separate prerequisite call, never combined with the update.
6. **Verify and recover.** Re-fetch exact item/Project/content identity and Status field/option; compare protected observed Issue state and unrelated scoped values. Persist response and verification per item before dependents. Timeout is uncertain: re-read; intended Status permits recovered observed outcome without claiming actor attribution, differing Status stops for review. Do not repeatedly force Status against automation or auto-revert. Partial batches report each item separately; continue independent items only under explicit manifest policy.

## Outputs and quality checks

Timestamped bounded snapshot or no-write delta table; after authorized execution, per-item attempted/verified/partial/blocked/uncertain outcomes with exact identity/field/option mappings, discrepancies, completeness and retained paths/actions. Reads may remain chat-only; saved snapshots use explicit approved artifact/evidence paths. Mutation records always use COMMON's durable approved path, collision and retention rules; no implicit cleanup. Verify no accidental Issue state/body/label changes were requested; disclose unexpected observed changes without asserting causality.

See [scenarios](scenarios.md). Excludes workflow configuration, field/option creation, other field types, ranking, archive/delete, Project creation/visibility changes, PR/draft mutations and atomic/CAS promises. A read-back establishes observed state at that time, not permanent workflow compliance.
